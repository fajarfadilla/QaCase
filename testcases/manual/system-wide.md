# System-wide (Manual)

## Assumptions

The case leaves these behaviours unspecified. The test cases below are written against these assumptions.
| ID | Ambiguity | Assumption | Affects | Question for PO |
|----|-----------|------------|---------|-----------------|
| AS-33 | The product is multi-tenant, but isolation rules are not stated | An Employee belongs to exactly one Tenant and can only see or select that Tenant's data in WeMine, WeMineOffice and the API; another Tenant's records return "not found" or "access denied" | SW-M-001, SW-M-002, SW-M-003 | Can an Employee belong to more than one Tenant (e.g. a contractor working for two mining companies)? |
| AS-34 | Offline operation is a core goal, but sync behaviour is not described | Records created offline are queued with a visible pending count, survive app restarts, and sync automatically once online without duplicates | SW-M-005, SW-M-006, SW-M-008, SW-M-019 | Is there a manual "Sync now" option? Are records synced in the order they were created? |
| AS-35 | What happens when Master Data changes after a record references it is not described | A pending record whose Area or PIC was removed is never silently dropped: it either syncs or fails with a clear, fixable error. Synced records keep showing the values they were submitted with | SW-M-009, SW-M-010, SW-M-013 | What should happen to a pending Hazard whose Area was deleted or whose PIC was deactivated before it synced? |
| AS-36 | Only the first Master Data download is described (Flow 0) | WeMine has a manual Master Data refresh; a refresh while offline fails gracefully and keeps the cached data | SW-M-011, SW-M-012 | When is Master Data refreshed: manually, on app start, periodically, or pushed by the backend? |
| AS-37 | Signing out with unsynced records is not described | WeMine warns that pending records will be lost before signing out | SW-M-014 | Should sign-out be blocked until everything has synced, or only warned? |
| AS-38 | Session lifetime and offline expiry are not described | An expired session doesn't interrupt offline work; on reconnecting the Employee signs in again and pending records then sync under the original Employee | SW-M-015 | How long does a session last? What happens to pending records if a different Employee signs in on that device? |
| AS-39 | WeMineOffice must work "even when having a bad internet connection or not having one at all", but no offline behaviour is described for it | WeMineOffice shows an offline indicator and never loses unsaved changes; they are saved automatically or can be saved once back online | SW-M-018 | Which WeMineOffice features must work fully offline? |
| AS-40 | Using one account on several devices is not mentioned | An Employee can be signed in on more than one device; each device syncs its own records and every device shows all of them after sync | SW-M-016 | Is signing in on multiple devices allowed at the same time? |
| AS-41 | App updates are not mentioned | Updating WeMine keeps the session, cached Master Data and pending records | SW-M-017 | Can an app update ever require clearing local data? |
| AS-42 | "Bad internet connection" is named as a target condition, but retry behaviour is not described | Failed requests and photo uploads are retried automatically; an interrupted upload never produces a partial or corrupted photo | SW-M-007 | Are uploads resumable, or retried from the start? Is there a retry limit? |
