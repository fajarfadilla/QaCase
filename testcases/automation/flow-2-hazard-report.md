# Flow 2 - Safety Hazard Report (Automation)

## Assumptions

Product assumptions for this flow are listed in [manual/flow-2-hazard-report.md](../manual/flow-2-hazard-report.md#assumptions). These are specific to automation.
| ID | Ambiguity | Assumption | Affects | Question for PO |
|----|-----------|------------|---------|-----------------|
| AS-43 | No real WeMine environment, APK or API is available | Automation specs are examples only: they are written against the assumed API and UI but are not run, because there is no environment to run them against. CI only checks that they compile and are discovered | HZ-A-001 – HZ-A-011 | Is there a test or staging environment and a test build we can target? |
| AS-44 | Microsoft SSO can't be automated reliably, and no test accounts are available | Specs get a token for each test account from a test-only auth helper instead of signing in through Microsoft; the real Microsoft login is covered by manual cases | HZ-A-001 – HZ-A-011 | Can the test environment issue tokens for test accounts without the Microsoft UI? |
| AS-45 | The case gives only three API paths (`/user/who`, `/user/me`, `/tenant/master`) and no methods, payloads or status codes | Every other path, and all methods, payloads and status codes, are assumed and documented in `automation/README.md` | HZ-A-001 – HZ-A-010 | Where is the API specification (e.g. OpenAPI)? |
| AS-46 | No way to observe notifications in a test is described | The test environment exposes the notifications each Employee received through a test-only helper, so specs can assert who was notified | HZ-A-004, HZ-A-005, HZ-A-010 | Does the Notification Service have a test hook or sandbox for asserting deliveries? |
| AS-47 | How the backend avoids duplicates from retries and offline sync is not described | Every record carries a client-generated ID; the backend treats a repeat with the same ID as the same record | HZ-A-010 | How does the backend deduplicate retried or re-synced submissions? |
| AS-48 | The WeMineOffice and WeMine UIs are not available to inspect | Web and mobile specs find elements by assumed labels and accessible names (e.g. an "Add Field" button) | HZ-A-011 | Do WeMineOffice and WeMine expose stable test IDs or accessibility labels for automation? |
| AS-49 | No WeMine build, app ID or target platform is given | The Maestro flow targets an Android test build with app ID `com.wemine.app`, on an emulator where airplane mode can be toggled | HZ-A-011 | Is WeMine built for Android, iOS or both? Is there a test build and what is its app ID? |

## Test Data

The test environment is seeded with the Tenant A and Tenant B people and places from [Flow 2 Test Data](../manual/flow-2-hazard-report.md#test-data), with usernames `rina`, `paul`, `maya`, `omar`, `sam` (Tenant A) and `tara` (Tenant B). The notification helper only returns notifications sent during the current test (AS-46).
